# Invitation signup and split login UI

The approved 28 October invitation-only design and V4 wrapped-metal Blender still are implemented as semantic components. Login continues to call the unchanged existing sign-in action and retains generic credential failure, native validation, current-password autocomplete, pending locking and the existing destination. Added password visibility controls do not block paste or change password bytes.

Signup is a distinct /signup route. Since invitation verification/activation is not implemented, that route always presents an honest unavailable invitation state, ignores query strings and exposes no credential form. Valid, expired, invalid, used and existing-account presentations are reviewable through the fixture harness. Valid email comes from supplied presentation data, never browser query text. The review form collects fictional values locally, validates required fields and exact confirmation, shows pending and a clear no-account-created result, clears the fields and sends nothing. Without hydration it is disabled. No password-strength policy is derived from the picture; the existing 1024-character input ceiling is retained, and actual enrollment/password policy and server activation remain separate work.

Artwork: original supplied Blender V4, Library pack libfile_b39d53f5a4bc81919e669fa6c337223f. Four files are integrity-checked against their supplied manifest. Responsive WebP widths 600/900/1200 with PNG fallback; full 5:7 composition is retained on desktop and mobile. Native text and forms are never baked into art. Opaque studio background, not live refraction. Static at all motion preferences; no 3D runtime or autoplay. Official existing brand asset is reused.

Review-only state selectors and sample email are confined to the external fixture entry. They are not server invitation evidence. Home, heart Journey, checkpoint, database, auth configuration and credentials are unchanged. No invitations were sent or accounts activated. Local source/browser checks do not establish live invitation or authenticated sign-in success.

Before live activation: define the server invitation lookup and single-use redemption contract, owner/reissue/expiry rules, authoritative name policy, supported password policy/verification and success destination. Implement server revalidation and authorization independently of client fields; fail closed until available. No API or auth grants are invented by this presentation slice.
