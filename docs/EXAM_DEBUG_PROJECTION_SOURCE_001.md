# Exam1 q8 repair-source and evidence bridge

This is disabled source composition over required future native ports. It does
not enqueue a Judge job, install SQL, activate q8 execution or establish live
grading. The approved policy remains nine functional points in ordered groups
3/2/2/2, four manual counterexample points and two manual explanation points.
Only the published frozen rubric supplies points; the host report supplies
complete group pass/fail observations, never scores or manual marks.

## Actual gap confirmed across Go and TypeScript

The generic ABI3 profile can express the approved repair function, but current
Go scored Storage keys, scoring manifests, host-report publication and native
functional context remain q1-q5-only. `judge.jobs.submission_id` references
`app.submissions`, whereas a structured q8 answer has a separate immutable answer
receipt. The existing scoring-acceptance trigger treats a code submission as
coding and rejects a debug rubric. Reusing the receipt as an execution submission,
clearing checkpoint metadata or using a legacy key is not a valid solution.

No Go, schema, role or existing q1-q5 producer behavior is changed here.

## Implemented source boundary

- Explicit q8-only manifest preparation and report capture share the existing
  functional wire ABI. They validate exact private/public case-file and raw case
  hashes, unique complete case coverage, ordered criterion bindings and the fixed
  four-group rubric. Existing coding APIs and the existing native producer still
  reject q8. Intrinsic byte bounds prevent shadowed byte metadata, getters or
  shared/resizable/detached storage from bypassing capture.
- `prepareScoredExamDebugProjection` validates one canonical accepted whole
  `debug_with_reason` JSON answer, its exact contract/hash/size, original receipt,
  owner/auth/cohort/checkpoint attempt/request/ordinal/time, frozen publication,
  evaluator route, pending intake outbox and approved rubric/source provenance.
- It extracts `source` into exactly the published ABI3 `learner_file`, preserving
  every UTF-8 byte, CRLF, whitespace and final newline. It does not insert a
  package, rename the function or project explanation/counterexample prose into
  executable input. Whole-answer SHA256 and projected-source SHA256 remain
  distinct and both are bound into the projection digest. Changed reasoning
  therefore changes whole-submission/projection identity even with the same code.
- The projection contains an immutable proposed job request with the exact frozen
  evaluation specification, pack/manifest/case digests and groups. Its
  `runtimeEnabled:false` is a status marker, not a native authorization proof.
- `createScoredExamDebugBridge` requires explicit reader, verified private-pack,
  job/terminal reader, protected publication outbox, scoring client and bounded
  settings. Missing ports leave the bridge unavailable before client-method
  access. Construction makes no connection and no queue insertion.
- `prepareProjection` obtains and rechecks the accepted source through the
  reader. `prepareEvidence` requires a separately created native mapping to a
  distinct projection UUID, internal execution-submission UUID and job UUID. It
  checks source-artifact filename/size/hash and exact proposed scoped key, frozen
  snapshot/spec/report/manifest/group linkage, original receipt identity and
  current scoring revision, then stores and reads back an exact immutable
  publication envelope before any scoring-event write.
- `record` uses the existing restricted scoring writer against the ORIGINAL
  structured receipt and WHOLE answer digest. It awards no manual points and
  creates no new learner acceptance, graded debit or exam attempt. Complete false
  group observations remain false; absent/malformed/infrastructure reports are
  unavailable and create no invented zero or success event.
- Publication has an original deadline, owned pending latch and exact retained
  envelope. Unknown acknowledgement remains uncertain; explicit retry cannot
  rebind to a new answer/revision/job. A later denial does not erase earlier
  uncertainty. No automatic retry, pool close or role mutation is introduced.

## Exact unimplemented native contracts

These are SOURCE/adapter gaps, not merely tests waiting to run:

1. A reviewed native q8 context reader must verify current evaluator authority,
   authentic accepted receipt/outbox/debit, pinned full publication and valid
   original acceptance time/closure. Current active/intake checks must not discard
   historically accepted answers after exam expiry. No such reader is supplied.
2. A private artifact adapter must verify authentic approved content/review
   provenance and actual pinned pack bytes. Well-shaped hashes or message IDs
   alone are not authority. No pack is fabricated or published by this slice.
3. A native projection ledger and queue adapter must create exactly one DISTINCT
   internal execution identity/job idempotently for a projection, bind the full
   actual immutable snapshot/target/resource/owner/artifact tuple, and reuse the
   original structured learner acceptance/debit. No ledger, upload or enqueue SQL
   is supplied. The proposed key is in `nextera-submissions`:

   `<auth_user_id>/<cohort_id>/scored-exam-v1/<checkpoint_attempt_id>/q8/<projection_id>/<source_sha256>`

   Its auth owner is not the internal learner ID. Current Go deliberately rejects
   this q8 key; no fallback to legacy or q1-q5 keys is allowed.

4. Go weighted q8 execution, durable host-report capture and an authoritative
   terminal-result adapter remain required. That adapter must prove an actual
   persisted terminal execution/acknowledgement, exact execution-attempt UUID,
   result digest and complete trusted host report for the bound job/snapshot.
   DTO syntax/linkage checks in this bridge do NOT establish that native proof.
   Binary PASS/FAIL, container exit or a caller acknowledgement flag cannot
   substitute. Queue lease tokens must never enter these DTOs or evidence.
5. Durable publication retention, discovery/claim/lease, restart recovery and
   native role/ACL/concurrency/cancellation behavior remain unverified. No
   production route is configured by this source package export.
