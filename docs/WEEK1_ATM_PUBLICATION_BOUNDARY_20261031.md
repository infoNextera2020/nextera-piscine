# ATM publication preparation boundary — 31 October 2026

The existing importer writes an ordinary curriculum version and automatically publishes when evaluation projections are supplied. That path has no persistence/readback for `CurriculumNode.projectSource` resources and no configured ATM release/capture activation check. Importing that data would silently drop the resource descriptors and could publish an incomplete project. The source manifest's development status does not prevent that behavior.

`packages/db/operations/curriculum.ts` now rejects this exact family at function entry, before reading any DB method or entering a transaction. Any plain ATM projectSource descriptor presence, ABI4 execution projection or root semantic_profile_digest presence triggers `AtmPublicationPreparationError`, code `ATM_PUBLICATION_PREPARATION_REQUIRED`. The check includes the actual nested resolved checkpoint-task spec locations, so stripping the outer marker does not bypass it. Null/empty markers and caller-supplied ready/published flags do not activate anything.

The error identifies three missing capabilities:

1. `content_addressed_public_resource_persistence_and_authorized_readback`: persist and verify the source-package/profile/public-resource identities and exact bytes, and deliver them only under the existing authorized curriculum/attempt context. Do not silently drop the starter, reporting profile, demos, references or release metadata.
2. `explicit_cohort_schedule_activation_independent_of_exam1_result`: supply, persist and recheck the actual server-owned cohort schedule/release configuration. A graph root is not a release schedule. Do not invent dates/offsets or add an Exam 1 pass gate.
3. `abi4_trusted_capture_registration_and_result_activation`: bind the actual approved pack/images/resources/model/profile and private ordered case manifest to positively proven host stdin delivery, raw stdout/stderr capture, clean termination and durable capture/result receipts for the exact submitted source/team attempt. Missing producer/registration/proof cannot become PASS. Existing exact-team/mentor/progression gates remain separate required checks.

Future native persistence and activation must implement and verify those capabilities before a deliberately reviewed importer path replaces this source-only rejection. No boolean/JSON ready flag or caller assertion can enable the current path. This milestone adds no schema, SQL, native API, runtime producer, role, credential, schedule default or grade writer.

ATM source validation and compilation remain usable: the standalone source validator still checks the real v2 public package and reports runtime readiness not proven; compiler tests still resolve an explicitly configured synthetic source fixture. The importer rejects ATM even without evaluations because its current draft receipt also has no place to retain the resources. Clean legacy draft imports and legacy/scored publication logic are unchanged.

Verification calls the real importer only with fake DBs. A strict proxy fake records any DB access and proves ATM/ABI4/semantic inputs cause zero method lookup, transaction, SQL or publication. In-memory legacy fakes preserve draft and publication behavior; the existing seven scored publication fake tests remain green. No real importer, database, publication or service is invoked by these checks.

Publication inputs are copied and frozen from plain data before the first database method access or await, without invoking getters. This keeps the family exclusion stable if a caller later adds a source descriptor or replaces a projection while a fake/real transaction is pending. The original marker-free legacy snapshot is used; injected ATM metadata is never published or silently dropped. Caller objects remain mutable and unfrozen. Valid finite fractional CPU values and optional undefined fields retain their legacy values. Accessors/cycles/non-data objects are rejected before DB access rather than executed as publication input. Existing marked canonicalization and publication SQL/branches stay intact.
