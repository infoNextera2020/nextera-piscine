# Protected public Run subprocess adapter

Source only; no public Run service or production policy is enabled by this change. `createPublicRunProcessExecutor` implements the existing `FencedPublicExecutor` consumed by `executeQueuedVisibleRun` and `executeVisibleRunBatch`. Configuration is explicit and server-owned: canonical absolute executable/socket paths, SHA256 of the reviewed worker binary, pinned sandbox image digest, cleanup grace and exit grace. There is no environment-based autostart, default image/socket, credential, arbitrary command, shell or client-selected executable.

Construction performs no IO. On an explicitly invoked execution, the Linux adapter verifies an executable regular file, rejects symlinks and group/world-writable files, validates its digest and pins the open inode through inherited fd3. It launches that inode with fixed CLI arguments and an empty environment, sends one bounded canonical public-only envelope on stdin, then closes stdin. Exact source bytes, definition, manifest/policy digests, deadline and deterministic run/generation identity are preserved. Lease credentials and private grading packs are not transported. An open fd prevents pathname replacement races, not in-place writes by its trusted owner: runtime preparation must keep the reviewed binary immutable during execution, use atomic replacement for updates, and verify ownership/access. Source tests are not evidence of that operational protection.

The Go adapter's currently supported ABI is `go_function_v1`, package `main`, string/int64 input and string return. Incompatible package names or runtime profiles fail closed; no source/package rewriting occurs. Its existing fixed engine profile is checked for compatibility, not installed as a selected Run policy. Operator configuration must separately supply resource policy/manifests before work can be enqueued. Go compilation and learner execution remain separate budgets.

Receipts are collected as bounded raw bytes and decoded with strict UTF8. The wire cap accounts for Go JSON escaping expansion separately from the decoded learner-output cap. Only one flat seven-field receipt is accepted; duplicate/unknown keys, trailing JSON, malformed Unicode, mismatched bindings, unsafe output, stream errors or nonzero exit fail closed. Infrastructure text is suppressed. A process exit cannot manufacture a verified container-stop proof.

Abort, lost authority, deadline or watchdog requests cooperative SIGTERM, allowing the Go supervisor's independent 15-second cleanup budget. The explicitly configured grace must include at least one second of control/receipt headroom beyond that budget; then SIGKILL and a bounded final wait prevent an orphaned local supervisor from blocking forever. These are supervisor compatibility requirements, not selected learner Run allowances. Forced termination and uncertain transport leave capacity reserved for trusted reconciliation. A valid late proof after lease loss still leaves the existing driver in `recovery_required`; no official result, mastery, XP or graded attempt is affected.

## Verification and wiring boundary

Fake-process tests exercise the existing fenced driver with this actual adapter: successful completion is recorded only after a bound receipt; aborted work never completes even when a proof arrives. Tests also cover exact Unicode/CRLF bytes, read-only construction, fd/env/argv configuration, actual local fixture-file hash/mode/symlink checks, chunked UTF8 and expanded Go JSON output, malformed receipts, null proofs, deadline and cancellation races, forced stop, pipe errors and cleanup timers. `node:child_process` is mocked to throw on any default launch; no real program, Docker socket, service or container is executed by these tests.

The existing batch API accepts this executor explicitly. Runtime assembly is intentionally absent: no worker credentials, migration application, queue polling loop, environment enablement or new listener is added. A separately approved rehearsal must verify the actual pinned binary and image, inherited-fd launch, resource enforcement, cancellation, verified cleanup, crash recovery, SQL fencing and lease-loss handling together. Authenticated code execution remains unverified by these source tests.
