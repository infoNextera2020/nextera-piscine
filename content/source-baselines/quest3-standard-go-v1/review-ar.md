# مراجعة Quest 3 للمبتدئ

مسودة v1 — 29 أكتوبر 2026 — الاتجاه معتمد والتفاصيل للمراجعة

## النتيجة التعليمية

المتعلم يفرق بين دالة ترجع قيمة، ودالة تطبع، ودالة تغيّر قيمة يراها المستدعي. بعدها يستخدم نفس الفهم مع نص قصير وأرقام وقائمة. لا نعيد Q2، ولا نضيف تمارين لمجرد الحفاظ على عدد المستودع.

## الترتيب الملموس

1. StrLen: جسر string وbyte وrune، ثم العد؛ مثال Go له2 bytes و2 runes، و«باب» بلا تشكيل لها6 bytes و3 runes.
2. PointOne: صندوق لقيمة وسهم يشير إليه، ثم تغيير القيمة عند المستدعي.
3. Swap: صندوقان وتتبع القراءة والكتابة قبل ضياع قيمة.
4. DivMod: شرح صغير للقسمة الصحيحة والباقي ثم وضع النتيجتين في targets منفصلة.
5. BasicAtoi: نص ASCII صحيح فقط وتحويل تدريجي حسب القيمة المكانية.
6. BasicAtoi2: رفض المدخل كله عند أي حرف غير مسموح، بما فيه الفراغ.
7. Atoi: إضافة إشارة واحدة اختيارية، دون قفزة إلى overflow أو error API.
8. SumSlice: تمرين جديد يصل accumulator في Q2 بقائمة قيم؛ يختبر empty وnil وعدم تغيير المدخل.
9. StrRev: عكس ترتيب runes بعد فهم slices، لا عكس bytes ولا ادعاء معالجة graphemes.

بين المراحل تجارب صغيرة وتوقعات ورسوم، وليست كلها اختبارات إضافية. الحزمة فيها9 مهام أساسية:8 مقتبسة في هدفها من مصادر مناسبة +SumSlice جديدة. كل مهمة بها signature وملف مقترح وأمثلة وchecks وتلميح وسؤال فهم، دون حلول.

## العقود المقترحة المعلنة

- كل المهام functions في package محلية piscine؛ caller منفصل يعرض النتيجة أو القيم بعد الاستدعاء باستخدام fmt. لا output داخل الدوال المطلوبة. رفع ملف الدالة فقط وفق عقد يحتاج اختبارًا تقنيًا قبل التفعيل.
- PointOne وSwap تستقبل pointers صالحة غير nil؛ Swap يستقبل عنوانين مختلفين. DivMod يضمن a من0 إلى100 وb من1 إلى10، ونتيجتين في عنوانين مختلفين؛ لا قسمة على صفر أو aliasing أو signed arithmetic مفاجئ.
- parser يقبل ASCII digits فقط؛ مدخلات قصيرة حتى8 runes تمنع مفاجآت overflow. BasicAtoi يستقبل نصًا صحيحًا غير فارغ فقط. الخطوتان التاليتان تحددان النص الفارغ والفراغات والإشارة المنفردة والمتكررة صراحةً، والخطأ يرجع0.
- StrLen وStrRev تستقبل valid UTF-8 حتى32 runes. StrRev يعكس runes، ولا يدعي سلامة عكس النصوص ذات العلامات المركبة أو emoji المتصلة. الأمثلة الأساسية تستبعد تلك التعقيدات.
- SumSlice تقبل0 إلى20 قيمة من-100 إلى100؛ empty وnil نتيجتهما0، ولا تغيّر العناصر.
- نطلب بناء العد والتحويل والعكس للتعلم بدل استدعاء دالة جاهزة تؤدي المهمة كلها. هذا هدف معلن، وليس ادعاء وجود فاحص قيود أو grader مطبق.

الحدود الرقمية وأسماء الملفات وهذه التوضيحات **تفاصيل مقترحة للمراجعة**، لا حقائق منقولة كلها من المستودع ولا اختبارات خفية معتمدة.

## ما لم ندخله

printstr الأصلي مستبعد وفق طلب إزالة الأسئلة المرتبطة بـz01؛ موجود كرابط تاريخي فقط ولا يظهر اسمه أو الاعتماد المحذوف في نص المتعلم أو البنك النشط. لا تعويض آلي بسؤال طباعة مماثل. UltimatePointOne وSortIntegerTable خارج الأساسيات الحالية؛ UltimateDivMod امتداد مؤجل. ملفات المصدر لم تُحذف أو تُعدّل.

## المراجعة والتشغيل

بنك المحتوى يحتوي خمسة قوالب وسؤالًا خاصًا لكل مهمة؛ ليس بنكًا عشوائيًا منشورًا أو كافيًا وحده لتنوع السحب. نحتاج variants مناسبة للنشاط قبل تشغيل سحب5 أسئلة. التوزيع التلقائي غير التبادلي للزملاء وتعيين المرشد والإتاحة المستقلة عن الاعتماد كما اتُفق؛ الإتقان وXP بعد المرشد. لا أرقام درجات أو XP أو retry policy جديدة.

مع60 طالبًا و3 مرشدين، جولة واحدة لكل طالب تعني60 مراجعة بمتوسط20 عند التوزيع المتساوي؛ لا نحول ذلك إلى زمن متخيل. التجارب القصيرة بين المهام تقلل القفزات ولا يلزم تحويلها لجولات مراجعة مستقلة.

## قبل الاستيراد

نراجع الحدود والعقود، ثم يختبر الفريق starter وcaller والرفع والحالات الصحيحة والخاطئة والتغذية الراجعة. لم تُشغّل حلول طلاب أو كود المستودع، ولا نعلن جاهزية grader من نص تعليمي. الموارد الرسمية تم فتحها في29 أكتوبر2026، وتُقرأ منها أجزاء قصيرة عند الحاجة فقط.
